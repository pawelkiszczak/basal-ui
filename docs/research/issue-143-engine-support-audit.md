## Findings for dependent work

### Recommendation explanations and limits

There is no Engine recommendation service to adopt. Basal-ui's `catalog.py` owns candidate selection and explanation. It checks machine compatibility, installed Backend, model architecture/format, estimated memory, and available memory now; it favors a comfortable fit and current-family variants. Quality and speed slots are tier/format heuristics, not measured benchmark rankings. Estimates neither reserve memory nor replace an Inference test; actual loads still pass Fleet budget/reservation checks. Memory estimates use checkpoint size and a fixed overhead, so runtime memory fit can differ.

The function can return up to **five named slots**: `recommended`, `best_quality`, `fastest`, `lightest`, and `multimodal`. The first three are omitted without eligible runnable text families; `best_quality` and `fastest` are additionally omitted when their candidate duplicates another core slot. `lightest` needs a runnable recurrent model; `multimodal` needs a media-capable variant that is not too large (it can fall back to a tight fit). The frontend renders one card per returned slot; it does not merge duplicate model IDs into a shared suggestion card (the separate All models table maps each ID to only one slot label). The code says a basal-omni-only result can occur when it is the only qualifying fallback family and/or the independent multimodal candidate; it cannot establish why this reporter saw that result without the request-time catalog assessments, hardware/available-memory data, Backend checks and returned suggestion payload. ([slot selection](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/catalog.py#L576-L691), [card rendering](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/static/app.js#L152-L170), [per-slot cards](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/static/app.js#L208-L221))

### Gateway MCP

Upstream Engine supports MCP directly, but its transport is not the discoverability request. Baseline exposes the **MCP at /mcp** checkbox and an **MCP** tab with a copy-ready connection snippet in the **API server** view; saved enablement applies after restart. There is no MCP category or direct MCP setup link in the separate Settings categories. Gateway imports Engine `basal.mcp_server.http`, routes decisions through Fleet, and conditionally passes loaded model IDs using the `mcp_models` feature probe. Thus classify MCP as Partial: released transport exists, while discoverability remains a basal-ui navigation/guidance task. Source inspection verifies controls and route construction, not a live MCP handshake, API-key behavior, or routed inference. ([baseline API server controls](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/static/index.html#L60-L64), [load and saved setting controls](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/static/app.js#L1734-L1745), [Engine transport integration](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/gateway.py#L245-L274))

### All-time totals versus chart history

Persisted lifetime Usage is an aggregate per model: counts, totals, first/last-use timestamps, and bounded latency samples. It can answer an **All time total** query, but it cannot reconstruct daily or hourly buckets. History has a timestamp per record, but retains only the newest 2,000 records by default and does not cover every inference path (ordinary basal Batch is excluded). A chart labeled **All time** therefore needs an explicit source/coverage policy; summing retained History would not equal persisted lifetime totals. ([aggregate schema](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/stats.py#L54-L67), [dated History rows](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/history.py#L105-L127), [History retention](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/basal_ui/history.py#L162-L175), [Batch coverage note](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/docs/USAGE.md#L341-L349))

### Shipped and Selected calibration

Engine resolves a Shipped calibration for a model/execution configuration and accepts an explicit `--calibration` file. Basal-ui's Selected calibration is a persisted UI choice passed when a model loads. The baseline checks model/revision/layout/configuration compatibility and shows warnings when selection differs from Active load settings. Thus Engine provides calibration mechanics; explaining, selecting, importing, and applying a compatible file through the product belongs to basal-ui. These terms follow [GLOSSARY.md](https://github.com/pawelkiszczak/basal-ui/blob/7b830a9df430146f42919c7a8234a76db1ddcc91/GLOSSARY.md).

## Evidence limits

The release tag, `main` SHA, basal-ui gate, checked-in UI behavior, and source-level contracts were inspected. No basal-serve child, real model, MCP client, calibration fit, browser session, or hardware memory counter was exercised. Therefore this audit cannot establish runtime availability of optional dependencies, actual load-time feedback, cache metric freshness under contention, RSS accuracy on a given host, or model compatibility on user hardware. The current `main`/release source equality is specific to the recorded commit snapshot.
